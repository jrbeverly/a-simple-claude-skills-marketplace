# CODEMAP — skills-marketplace

Repository-specific structure, technology stack, and implementation patterns.

## Purpose

This repository defines a **skills marketplace**: a standard for packaging, indexing, and installing Claude Code skills. It provides the specification documents, catalog generation tooling, and installer that together form the marketplace infrastructure.

Skills are self-contained packages (manifests, prompts, scripts, templates) that extend Claude Code with specialized behaviours. This repository hosts the skill catalog and the tooling to build, validate, and distribute it.

## Top-level layout

```
skills-marketplace/
├── skills/         # Skill packages (content, per <namespace>/<name>/)
├── index/          # Generated catalog index files
├── docs/           # Human-facing documentation and specifications
├── scripts/        # Tooling source code (service-scoped subdirectories)
├── tests/          # Automated tests (mirrors scripts/ structure)
├── examples/       # Example skills and catalog for validation
├── CODEMAP.md      # This file
├── README.md       # Project overview
└── VISION.md       # Project vision
```

Full layout specification and directory purpose statements are in **[docs/specs/marketplace-repository-layout.md](docs/specs/marketplace-repository-layout.md)**.

## Technology stack

**Current state:** Specification and early tooling phase. The catalog index generator is built; the installer is next. The actual technology stack in use differs from the repository-wide preferences — deviations are documented below.

| Layer | Technology in use | Notes |
|-------|------------------|-------|
| Tooling (generator, installer) | Bash | All marketplace tools are Bash scripts with `git`, `jq`, and `yq` as the only runtime dependencies beyond a POSIX shell. |
| Catalog format | JSON (`catalog.json`) | Generated by `scripts/catalog/generate-index.sh`. |
| Manifest format | YAML (`skill.yaml`) | Parsed by `yq` at tool runtime. |

## Build and test

**Build:** `make index` (or `bash scripts/catalog/generate-index.sh` directly) regenerates `index/catalog.json` from the skills in `skills/`. Dependencies: `jq`, `yq`, `sha256sum`.

**Test:** `bash tests/catalog/test-generate-index.sh` runs the catalog generator test suite. Tests cover snapshot matching, idempotency, and empty-input behaviour.

**Local validation:**
```bash
make index                          # Regenerate catalog
bash tests/catalog/test-generate-index.sh  # Run tests
```

## Architecture patterns

**Service-scoped structure:** All source code lives in service subdirectories — no files directly in `scripts/` or `tests/`. New tools get their own subdirectory pair (`scripts/<tool>/` + `tests/<tool>/`).

**Generator-consumer split:** The index is generated by `scripts/catalog/`, written to `index/`, and consumed as read-only by downstream tools (installer, CLI, web UI).

**Content vs. code:** `skills/` is content (skill packages), not source code. It's organized by `<namespace>/<name>/` for the same collision-avoidance and scaling properties as service-scoped directories.

**Identity everywhere:** The `<namespace>/<name>` key is the universal skill identifier — used in repository paths, catalog entries, and install targets (`~/.claude/skills/<namespace>/<name>/`).

## Key invariants

- No source files at the top level of `scripts/`, `tests/`, or any source-code directory.
- The catalog index (`index/catalog.json`) is generated — never hand-edited.
- All specification changes follow the proposal process defined in each spec.
